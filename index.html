TQMS/Triage Reference

        

          

            
How I triage a defect

            
The severity ladder I apply, and what each level means in practice. Severity describes impact; priority describes urgency — they are not the same field, and conflating them is how release calls go wrong.

          

        


        

          

            
S1 · BlockerStop the release

            
Core business flow is unusable
Checkout fails, login is broken, data is lost or corrupted, the app crashes on launch. No workaround exists. This is a no-go on its own — I don't need a second opinion to hold the build.

          

          

            
S2 · CriticalFix before ship

            
Major function fails, workaround is painful
Wrong calculation in a report, a role seeing data it shouldn't, a payment edge case. Often found by boundary analysis rather than the happy path — which is exactly why the happy path alone isn't a test plan.

          

          

            
S3 · MajorSchedule it

            
Feature misbehaves, workaround exists
Validation message missing, a filter that ignores one case, inconsistent behaviour between web and mobile. Ships only with a decision on record — from the product owner, not from silence.

          

          

            
S4 · MinorBacklog

            
Cosmetic or low-impact
Alignment, truncation, copy errors, inconsistent spacing. Logged with the same rigour as anything else — a defect nobody wrote down is a defect that ships twice.

          

        


        

          
What goes in every ticket I file

          

            
    
              
  • Reproduction steps a developer can follow without asking me a question
    • 
              
  • Expected versus actual, stated against the requirement — not against my opinion
    • 
              
  • Environment — build number, device or browser, OS version, user role
    • 
              
  • Evidence — screenshot, recording, console or network log, SQL result where relevant
    • 
              
  • Severity and priority set separately, with a one-line justification
